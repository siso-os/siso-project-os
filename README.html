Reusable package · HTML-first · verification-gated

SISO Project Kit

The complete project-local operating system for cold-pickup agents and humans: architecture orientation, tasks, missions, resume state, sprint lanes, run packets, write claims, independent verification, delivery proof, capability discovery, durable knowledge, UI decision campaigns, and an optional Agent Fleet Runtime Pack.

Codex CLI and Claude Code can operate it directly. It does not own terminals, models, credentials, or global agent identity; optional providers may add persistent panes, routing, messaging, and telemetry while the Fleet Pack supplies portable project contracts and admission evidence.

Install it into a project

New repository

npx --yes github:sisodias/siso-project-os#v0.5.0 init . \
  --name "My Project" \
  --summary "What this software is" \
  --outcome "The user outcome it creates"

Existing repository

npx --yes github:sisodias/siso-project-os#v0.5.0 adopt plan . --json
npx --yes github:sisodias/siso-project-os#v0.5.0 adopt apply . --json
open .project-os/migration/project-kit-migration.html

Adoption creates missing files, retains identical files, appends only a thin runtime route to existing AGENTS.md/CLAUDE.md, and preserves every other collision for explicit review. It never silently overwrites a project authority.

What every new agent does

  1. Read AGENTS.md, the engine loader shim.
  2. Load .agents/skills/project-operator/SKILL.md, which points to the canonical HTML authority.
  3. Read PROJECT-OS.html and FILE-TREE.html.
  4. Run project-os onboard --json.
  5. Open the chosen canonical task, mission/resume state, and linked run packet.
  6. Reserve its concrete write set, return evidence, obtain independent verification, and land through a delivery receipt.
  7. Run project-os check --json before handoff.

Humans use .project-os/generated/onboarding.html and knowledge-onboarding.html; both are deterministic read-only projections over the same JSON/JSONL truth.

Six core packs plus optional Fleet Runtime

Architecture

Stable file map, required paths, normalized operations, ambiguity scoring, and a non-regression baseline.

Execution lifecycle

Tasks, mission ownership, immutable resumes, dependency-aware claims, sprint lanes, run units, packets, returns, events, gates, and terminal census.

Verification and delivery

Concrete write reservations, attempt receipts, independent verifier lineage, output classification, landing plans, and remote-SHA equality proof.

Knowledge spine

HTML authorities with embedded metadata, proof/decision/run ledgers, repo facts, edit maps, research dead ends, durable memory, and anti-amnesia views.

Capabilities

Bounded discovery of skills, agents, commands, recipes, and adapters; install/depend/project-local/adapter/omit ownership; provider doctoring and collision-safe scaffolders.

UI Hub

Task-linked intent, research, divergent directions, candidate manifests, generated comparison galleries, human review import, exhaustive decisions, implementation receipts, visual verification, and task evidence folds.

Agent Fleet Runtime

Optional versioned bootstrap, exclusive domains, elastic capacity, verifier reserve, machine gates, Sol/Luna contracts, durable callbacks, admission receipts, and Mission Control projections.

Install the optional Agent Fleet Runtime Pack

cp <package>/packs/fleet/fleet.bootstrap.example.json ./fleet.bootstrap.json
project-os fleet plan . --config fleet.bootstrap.json --json
project-os fleet init . --config fleet.bootstrap.json --json
project-os fleet check . --json

The complete plan must pass before any file is written. It refuses ownership overlap (including case-folded paths), reserved control-state scopes, missing or redirected repository/evidence boundaries, absent verifier capacity, secret-shaped values, machine pressure, incompatible Project OS versions, and differing existing content. Managed fleet contracts and write-once admission receipts are digest-checked. See docs/fleet-runtime-pack.html.

Upgrade without overwriting project authority

npx --yes github:sisodias/siso-project-os#v0.5.0 upgrade plan . --json
npx --yes github:sisodias/siso-project-os#v0.5.0 upgrade apply . --by agent-name --json
npx --yes github:sisodias/siso-project-os#v0.5.0 upgrade rollback UPGRADE-... --root . --by agent-name --json

Install manifests hash the files Project OS actually owns. Upgrades replace only unchanged managed files or files matching a checked-in historical release baseline, preserve project edits, take internal backups, and emit HTML+JSON receipts.

Format law

Canonical machine state is JSON or append-only JSONL. Every substantive guide, map, index, migration report, review surface, and generated cockpit is deterministic HTML with an embedded JSON contract. Markdown remains only where an agent engine requires a loader: AGENTS.md, CLAUDE.md, and SKILL.md.
