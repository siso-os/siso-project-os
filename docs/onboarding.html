Greenfield

npx --yes github:sisodias/siso-project-os#v0.5.0 init . --name "Project name" \
  --summary "What this software is" --outcome "The user outcome it must create"
npx --yes github:sisodias/siso-project-os#v0.5.0 onboard . --json
  1. Commit the installed operating structure.
  2. Verify project configuration, repository facts, and edit maps.
  3. Use the installed Codex/Claude loaders and declare optional provider routes only when needed.
  4. Create one observable outcome task.
  5. Add sprint/run coordination only when the work shape requires it.

Existing repository

npx --yes github:sisodias/siso-project-os#v0.5.0 adopt plan . --name "Project name" --json
npx --yes github:sisodias/siso-project-os#v0.5.0 adopt apply . --name "Project name" --json
open .project-os/migration/project-kit-migration.html
  1. Plan inventories current rules, task authority, docs, capabilities, generated paths, verification, UI artifacts, trackers, archives, and legacy Markdown without mutation.
  2. Apply creates missing assets, retains identical assets, and preserves every differing authority.
  3. Existing AGENTS.md/CLAUDE.md retain their bytes and gain one bounded runtime route only when absent.
  4. Resolve preserved authorities and migrate substantive Markdown through the HTML report.
  5. Run provider doctor, architecture check, build, and read-only project check.
  6. Cut over one canonical route at a time; retained external systems use one-way adapters.

An incomplete migration exits non-zero after safely installing non-conflicting assets. The report names every remaining decision.

Version upgrade and rollback

npx --yes github:sisodias/siso-project-os#v0.5.0 upgrade plan . --json
npx --yes github:sisodias/siso-project-os#v0.5.0 upgrade apply . --by agent-name --json
npx --yes github:sisodias/siso-project-os#v0.5.0 upgrade rollback UPGRADE-... --root . --by agent-name --json
  1. Plan is read-only and compares current hashes with the install manifest and checked-in release baselines.
  2. Apply stops before mutation when a project-authored collision is unresolved.
  3. Every replacement is backed up under the immutable upgrade record.
  4. Rollback refuses to overwrite any file changed after the upgrade.

Agent cold pickup

  1. Codex CLI reads root and nearest AGENTS.md; Claude Code reads CLAUDE.md and the routed root rules.
  2. Read PROJECT-OS.html.
  3. Run read-only onboarding and stop on integrity errors.
  4. Open one canonical task and linked execution context.
  5. Search repo facts, edit maps, docs, decisions, proof, runs, research dead ends, and memory.
  6. Choose a declared capability; the current CLI actuates and Project OS records. Use optional providers only for added orchestration.
  7. Teach back outcome, task, write fence, dependencies, human gates, verification, and return.
  8. Claim, execute, prove, classify, rebuild, check, and hand off.

Human path

Open the generated cockpit, address explicit human gates, blockers, and UI reviews, then record the answer in the owning canonical record. Never edit generated HTML.

UI decision path

Candidate manifest → deterministic gallery/review → downloaded response → exhaustive decision → chosen-direction implementation → same-commit verification → task-evidence fold. Verification does not close the task.

Handoff

project-os build
project-os check --json
  1. Update task/run truth.
  2. Attach commands, revision, and observation evidence.
  3. Classify durable outputs.
  4. Report PASS, FAIL, BLOCKED, and not-observed honestly.
  5. Name the next canonical record.
