Greenfield

npx github:sisodias/siso-project-os init . --name "Project name" \
  --summary "What this software is" --outcome "The user outcome it must create"
npx github:sisodias/siso-project-os onboard . --json
  1. Commit the installed operating structure.
  2. Verify project configuration, repository facts, and edit maps.
  3. Declare capability routes; do not copy Agent Base skills.
  4. Create one observable outcome task.
  5. Add sprint/run coordination only when the work shape requires it.

Existing repository

npx github:sisodias/siso-project-os init . --name "Project name" --dry-run --json
  1. Inventory current rules, task authority, docs, capabilities, generated paths, verification, UI artifacts, trackers, and archives without mutation.
  2. Choose one writer per concern; retained external systems use one-way adapters.
  3. Merge staged runtime rules deliberately.
  4. Classify knowledge through reviewed manifests; adopt active work before bulk history.
  5. Declare Agent Base and project-local boundaries.
  6. Model only active task-linked UI decisions.
  7. Build, inspect, check, and cut over one route at a time.

Collisions and unresolved authority choices stop that boundary without a partial install.

Agent cold pickup

  1. Read root and nearest AGENTS.md.
  2. Read PROJECT-OS.html.
  3. Run read-only onboarding and stop on integrity errors.
  4. Open one canonical task and linked execution context.
  5. Search repo facts, edit maps, docs, decisions, proof, runs, research dead ends, and memory.
  6. Choose a declared capability; Agent Base actuates, Project OS records.
  7. Teach back outcome, task, write fence, dependencies, human gates, verification, and return.
  8. Claim, execute, prove, classify, rebuild, check, and hand off.

Human path

Open the generated cockpit, address explicit human gates, blockers, and UI reviews, then record the answer in the owning canonical record. Never edit generated HTML.

UI decision path

Candidate manifest → deterministic gallery/review → downloaded response → exhaustive decision → chosen-direction implementation → same-commit verification → task-evidence fold. Verification does not close the task.

Handoff

project-os build
project-os check --json
  1. Update task/run truth.
  2. Attach commands, revision, and observation evidence.
  3. Classify durable outputs.
  4. Report PASS, FAIL, BLOCKED, and not-observed honestly.
  5. Name the next canonical record.
