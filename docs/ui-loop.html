UI Lab operating loop

Task-linked design decisions from grounded intent to real-surface proof. The campaign never becomes a second backlog.

intent → research → directions → candidates → review → decided → implemented → verified

1. Intent

Bind audience, scenario, primary action, scope, surface, source revision, and observable acceptance to one existing canonical task without selecting a layout.

2. Research

Separate current observation, proposal, and reference. Capture current flow, source revision, state/data shapes, dependencies, screenshots, constraints, unknowns, and shared comparison fixtures.

3. Directions

Create at least two materially different theses. Name the divergence axis, satisfied constraints, tradeoffs, eligibility, and origin. Origin never grants approval.

4. Candidates

Author candidates/manifest.json. It accounts for every campaign candidate exactly once, links direction and artifact, freezes screen/copy/data/shell/viewports, and caps projections at 24 candidates. Generated gallery/review pages are reproducible views.

5. Review

The static page downloads a schema-valid response and stores no canonical browser state. Import requires reviewer identity, manifest digest, one eligible selection, and rejection of every other eligible direction.

6. Decided

The durable decision matches the raw response, chooses one direction, rejects every other direction exactly once, preserves rationale/verbatim notes, hashes manifest and response, and fixes implementation paths and acceptance.

7. Implemented

The chosen direction reaches real application paths. Receipt evidence names changed files, source commit, checks, actual surface observation, deviations, unresolved work, and approved exceptions.

8. Verified

Executable and visual evidence proves the chosen direction at the exact implementation commit across agreed states/viewports. Browser faults are zero or explicitly excepted. Missing or failed evidence stays visible.

Fold into canonical task

Promote a ui-task-evidence receipt and evidence JSON resolved through task ID plus stable filename, never a lifecycle-folder path. The fold links decision, implementation, verification, revision, exceptions, and remaining work. It does not change task status.

Optional adapters

Adapters declare capability, inputs, output types, eligibility, limits, and fallback; each invocation writes a receipt. Secrets and provider runtime stay outside .uihub. Raw output cannot advance state.
