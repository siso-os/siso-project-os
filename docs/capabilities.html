Full-profile capabilities and adoption

The full profile makes project-local operating capabilities permanent and discoverable without turning Project OS into an agent runtime. Its canonical entry point is .agents/project-profile.json. Runtime discovery loads the thin .agents/skills/project-operator/SKILL.md shim, which resolves to the substantive .agents/skills/project-operator/OPERATOR.html authority.

Ownership semantics

ValueMeaning
INSTALLGeneric Project OS structure installed in every full-profile repository.
DEPENDBehavior supplied by a declared provider such as SISO Agent Base or Node.js.
PROJECT_LOCALRepeatable product or repository knowledge whose canonical source stays in this repository.
ADAPTERA bridge from an engine or project check into a Project OS contract or receipt.
OMITDeliberately excluded product, credential, model-policy, or machine-specific behavior.

The starter declares Node.js 20+ and Agent Base subagents, conduct, orchestrate, herdr, and agent-comms as dependencies. Doctoring resolves Agent Base from providerRoots or SISO_AGENT_BASE_ROOT; it embeds no workstation path and requires no secret.

Discovery and doctor

discoverProjectCapabilities(root, options) returns deterministic JSON for supported .agents, .claude, .codex, proven-recipe, and adapter routes. Scans are bounded by file count, depth, and bytes; do not follow symlinks; tolerate absent engine directories; and report invalid or ambiguous definitions.

doctorProjectCapabilities(root, options) validates the profile, manifests, role profiles, commands, verification adapters, runtime shims, and every required provider. Its result is directly renderable as generated HTML.

Non-destructive adoption

planFullProfileAdoption(root) inventories current capabilities and classifies each asset as create, identical retain, or differing preserve. applyFullProfileAdoption(root, options) applies only a collision-free plan with exclusive writes and rollback of files created by a failed attempt. It never rewrites an existing root runtime shim.

Claude discovers the canonical skill through root CLAUDE.md; Codex uses root AGENTS.md. Both are pointer-only runtime shims.

Project-local scaffold APIs

  • scaffoldProjectSkill → .agents/skills/<id>/SKILL.md
  • scaffoldProjectAgent → .agents/agents/<id>.json
  • scaffoldProjectCommand → .agents/commands/<id>.json

All are idempotent for identical content, reject divergent collisions, and use the one engine-neutral capability root. Command contracts store a program plus argv, never a shell string.

Shared-lane integration surface

src/capabilities.mjs:
  discoverProjectCapabilities
  doctorProjectCapabilities

src/adoption.mjs:
  planFullProfileAdoption
  applyFullProfileAdoption
  scaffoldProjectSkill
  scaffoldProjectAgent
  scaffoldProjectCommand

Generated capabilities.json should preserve these return contracts. Generated HTML remains a read-only projection and never writes a manifest.
