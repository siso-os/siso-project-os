SISO Project Kit specification

Status: implementation contract · Profile: complete-siso-project-kit · Date: 2026-07-29

Install the reusable operating patterns proven in a large live agent-operated project without importing its product facts, customer evidence, runtime credentials, machine paths, or historical state.

Boundaries

  • Project OS owns project-local records, schemas, HTML authorities, projections, migrations, and integrity gates.
  • Codex CLI, Claude Code, or another compatible agent CLI executes the core lifecycle directly.
  • Optional providers may own spawning, model routing, messaging, telemetry, and persistent terminal/pane control.
  • Applications own product code, credentials, deployment policy, endpoints, and project-specific adapters.
  • Checks diagnose and fail closed; they never repair authored state implicitly.

Hard invariants

  1. One canonical task ID; sprints, runs, UI campaigns, and external trackers reference it.
  2. Folder state and record state agree; terminal task records are immutable.
  3. Mission ownership, registries, write claims, sprints, runs, and delivery mutations use exclusive locks or atomic directory replacement.
  4. Write fences contain concrete repository-relative paths and cannot overlap without explicit sequencing.
  5. Dispatched packets are immutable and digest-pinned; amendments name their predecessor.
  6. A worker claim is never verification. Passed verification requires distinct actor and verifier identities and an in-fence changed-file verdict.
  7. Landed work names one candidate SHA and proves remote equality when push is authorized.
  8. Generated HTML/JSON is deterministic and never canonical.
  9. Optional runtime-provider capabilities are dependencies, never copied project authorities.
  10. Existing-repository adoption preserves every collision and reports unresolved authorities.

Format and discovery

JSON/JSONL is canonical machine state. Deterministic HTML with embedded JSON is the substantive operating interface. Engine-required Markdown files contain discovery and routing; the explicitly requested .agents/PAGE.md and .agents/HANDOFF.md add compact project and owner entry points. The append-only owners.log indexes material evidence. Nearest AGENTS.md rules win; the root router points to the project operator shim and HTML authority.

Release acceptance

  1. Greenfield init passes architecture, capability, lifecycle, knowledge, UI, and deterministic build checks.
  2. Existing-repository adoption preserves source bytes, reports collisions and legacy Markdown, merges only runtime pointers, and emits HTML+JSON migration evidence.
  3. All schemas self-validate and all canonical artifact families are traversed by read-only check.
  4. Strict UI campaigns account for every direction/candidate, import raw human review, link exact implementation and verification commits, and fold proof into the canonical task.
  5. Package inventory contains only runtime, templates, HTML docs, schemas, tests/scripts, and license.
  6. No protected source paths, product facts, customer data, credentials, or source-project names enter the public package.
  7. GitHub package install succeeds from the released tag.
