Agent Fleet Runtime Pack

This optional Project OS pack makes fleet policy inspectable without replacing provider runtimes. Project OS owns durable project contracts, eligibility receipts, and projections. Herdr or another configured provider owns process control, atomic slot reservation, model routing, messaging, and telemetry.

Operating order

  1. Read PROGRAM.json, POLICY.json, REPOS.json, PROCESS-PLAN.json, and the applicable domain record only after fleet check has bound their digests to PACK.json.
  2. Use canonical Project OS tasks, missions, runs, work claims, decisions, and qualification receipts.
  3. Preflight dependencies; for a writer, acquire an exact task/run/unit work claim with the target machine as its seat. Path matching is Unicode-normalized and case-insensitive, and fleet writes may not claim Project OS control paths.
  4. Record fleet eligibility, then require the provider to atomically revalidate claims, live assignments, verifier backlog, and machine thresholds while starting the process. Receipts are write-once, digest-bearing eligibility evidence and never reserve provider capacity.
  5. Run implementers and verifiers in isolated worktrees; a verifier names the canonical implementation owner or claimant, differs from that actor, and has no implementation write paths.
  6. Resolve evidence through its real path beneath the task evidence root and accept only regular-file references.
  7. Append durable callbacks; use provider messages only as prompt delivery.
  8. Rebuild the read-only Mission Control projection after canonical state changes.

State distinctions

Eligibility permits the provider to attempt an atomic compare-and-start. Process start, task completion, and independent qualification remain separate authorities; none implies another. Missing, malformed, or incompatible Project OS versions fail closed.
