Project capabilities

The canonical full-profile entry point is .agents/project-profile.json. It declares installed Project OS capabilities (INSTALL), shared runtime providers (DEPEND), repository-owned behavior (PROJECT_LOCAL), integrations (ADAPTER), and deliberate exclusions (OMIT).

One operator contract

Root AGENTS.md and CLAUDE.md route runtime discovery to the thin .agents/skills/project-operator/SKILL.md shim. That shim resolves to the substantive .agents/skills/project-operator/OPERATOR.html authority; no shim copies its body.

Bounded discovery

Read-only discovery inventories supported project-local skills, role profiles, commands, proven recipes, and adapters under .agents/, .claude/, .codex/, docs/proven-recipes/, .project-os/adapters/, and .uihub/adapters/. Duplicate identities are migration conflicts; discovery never decides which source wins.

Doctor and adoption

The doctor needs no credentials. Agent Base resolves from a provider declaration or SISO_AGENT_BASE_ROOT. Missing required routes fail with remediation.

Existing-repository adoption starts with a plan. Differing files are preserved, capability collisions are inventoried, project-local authorities are retained, and runtime shim changes become explicit merge actions.
